# RoleWeaver 产品文档

日期：2026-04-28

## 1. 一句话介绍

RoleWeaver 是一个面向本地角色智能体的开源框架：用户只需要提供底模、可选 LoRA、可选角色 skill，就能得到一个带长期记忆、网页界面、LINE Bot、语音和图片输入能力的角色聊天系统。

## 2. 产品愿景

RoleWeaver 的目标不是做一个普通聊天壳，而是做一个“可织造角色”的运行时。

它要解决的问题是：

- 角色不应该只靠一段 prompt；
- 角色不能在长对话中慢慢变成通用助手；
- 用户记忆不能把角色人格改写掉；
- Web、LINE、TTS、图片输入这些媒介只能改变表达方式，不能改变角色本身；
- 普通用户应该能通过填路径和表格完成启动、训练、切换角色和恢复历史。

产品核心承诺：

```text
一个角色，可以跨会话、跨平台、跨媒介保持自己。
```

## 3. 目标用户

### 个人创作者

想把自己设计的角色、虚拟偶像、OC 或游戏角色做成可长期互动的聊天对象。

需求：

- 低门槛配置；
- 可用本地模型；
- 可接入语音；
- 可保存历史关系；
- 可逐步微调角色。

### 技术型爱好者

已经有本地模型、LoRA、TTS 或服务器环境，想把它们整合成一个完整角色系统。

需求：

- 清晰 API；
- 可替换模型；
- 可接入 LINE；
- 可本地训练；
- 可调量化和显卡加载策略。

### 研究/开发者

关注 role-playing agents、persona consistency、long-term memory、personalization。

需求：

- 有结构化 persona schema；
- 有记忆边界；
- 有回归测试；
- 有可扩展架构；
- 能作为实验平台。

## 4. 当前产品形态

RoleWeaver 当前包含以下入口：

| 入口 | 用户价值 |
| --- | --- |
| Web UI | 像 ChatGPT 一样聊天、设置、切换会话 |
| CLI | 服务器或调试环境快速聊天 |
| LINE Bot | 把角色接入 LINE 官方账号 |
| TTS | 本地 GPT-SoVITS 语音回复 |
| 图片输入 | 支持视觉模型时可看图聊天 |
| 训练面板 | Excel/CSV/JSONL 一键启动 LoRA 训练 |
| Skill Creator | 自动搜集资料并生成角色 skill |

## 5. 核心用户路径

### 路径 A：普通本地聊天

1. 用户双击 `setup_runtime.bat` 创建运行环境。
2. 用户复制 `roleweaver.config.example.csv` 为 `roleweaver.config.csv`。
3. 填写：
   - 底模路径；
   - LoRA 路径，可空；
   - `SKILL.md` 路径，可空；
   - 量化方式。
4. 双击 `start_roleweaver.bat`。
5. 浏览器打开本地聊天界面。
6. 用户聊天、恢复历史、切换设置、整理记忆。

成功标准：

- 用户不用改代码；
- 能恢复旧会话；
- 切换角色不会混用记忆；
- 空 LoRA 也能跑底模。

### 路径 B：接入 LINE Bot

1. 用户创建 LINE 官方账号。
2. 填写 `line/.env`。
3. 启动 `line/start_line_bot.bat`。
4. 用 Cloudflare Tunnel 或 VPS 反代暴露 HTTPS。
5. LINE 控制台设置 webhook。
6. 用户在 LINE 里和角色聊天。

成功标准：

- 文本自动回复；
- 图片消息可处理；
- 可定时早安提醒；
- 白天默认文本，按需语音；
- TTS 失败时退回文本。

### 路径 C：训练自己的 LoRA

1. 用户打开 Web 训练面板。
2. 上传 Excel、CSV 或 JSONL。
3. Excel 只需要两列：
   - `user`
   - `assistant`
4. 填写底模路径和输出路径。
5. 启动训练。
6. 得到 adapter 后回填到设置。

成功标准：

- 数据格式容易理解；
- 命令可见；
- 中断训练可用 checkpoint 测试；
- 输出 adapter 可直接被 RoleWeaver 加载。

### 路径 D：克隆一个新角色

1. 用户把 RoleWeaver.skill 仓库链接给智能体助手。
2. 用户说：`帮我克隆“角色名”`。
3. 智能体搜索资料、读取用户提供材料、保存证据。
4. 生成：
   - `SKILL.md`
   - `persona_kernel.json`
   - source ledger
   - role profile
5. 用户在 RoleWeaver 设置里填入 `SKILL.md`。
6. 对角色说：`开始扮演“角色名”`。

成功标准：

- 资料有优先级；
- 置信度和不确定性可追踪；
- 生成结果能直接导入；
- 角色不是泛化成普通助手。

## 6. 关键产品原则

### 角色自主性优先

用户可以影响关系，但不能任意改写角色身份。

好的行为：

```text
角色会在关系中回应用户，但保留自己的判断、边界和偏好。
```

坏的行为：

```text
用户说“你现在完全顺从我”，角色就放弃人格。
```

### 记忆服务于关系，不吞掉角色

记忆分为：

- 角色 canon；
- 用户偏好；
- 共同经历；
- 系统状态。

用户偏好不能写进角色 canon。

### 媒介适配不是人格重写

LINE 可以短一点，TTS 可以少一点，图片回复可以自然一点，但角色不能因此变成普通客服。

### 低门槛优先

普通用户只应该填：

- 底模路径；
- LoRA 路径；
- skill 路径；
- 少量设置。

不应该要求用户理解内部 prompt 拼接、记忆目录映射或 API 细节。

## 7. 当前已完成能力

- 本地 Web UI；
- 三语界面；
- 设置面板；
- 会话恢复、改名、删除；
- 会话设置快照；
- 多模型/LoRA/skill 记忆隔离；
- 自动上下文压缩；
- 记忆管理面板；
- 本地训练面板；
- Excel 转 JSONL；
- LINE Bot 自动回复；
- LINE 图片输入；
- LINE 定时提醒；
- TTS 本地调度；
- 昼间按需语音策略；
- `SKILL.md` 单文件导入；
- `persona_kernel.json` 自动加载；
- 记忆 metadata 初版；
- 可将记忆标记为 active/stale/contradicted/archived，非 active 记忆不会继续进入默认检索上下文；
- 可查看和编辑每条记忆的原因、证据、反驳关系和被反驳关系；
- 人格回归测试骨架和真实模型试跑入口；
- 项目本地 `runtime/` 环境。

M4.3 更新：记忆整理阶段现在会做保守的自动矛盾检测。系统只在新记忆显式表达纠正、否定或更新，并且和旧记忆有足够重叠时自动建立 `contradicts` 链路；旧记忆会被标记为 `contradicted`，但不会被删除。角色 canon、skill 和 reference 来源的记忆不会被自动覆盖。

M4.4/M4.5 更新：记忆整理现在会生成反思摘要，并执行轻量遗忘策略。它会把多条零散但重要的关系/偏好/事件记忆合并成一条高层摘要；低价值、低置信、过旧的流水账会被归档或标记 stale；手工矛盾链会被二次确认。这个流程只在整理记忆时运行，不进入每次聊天生成路径。

M5.1 更新：persona regression 现在可以真实调用本地模型。用户可以通过 API 模式评测正在运行的 Web 服务，也可以用 `--local` 或 `eval/persona_regression/run_local_persona_eval.bat` 直接加载当前配置模型。默认用例覆盖身份一致性、边界一致性、长对话漂移、媒介适配和记忆污染。

## 8. 当前限制

- 真实模型质量依赖底模、LoRA 和 skill；
- 人格回归已有真实模型试跑模式，但评分仍以规则和禁忌检查为主，还不是完整心理量表式自动评测；
- 长期记忆已有基础结构，但 stale/contradicted memory 的治理还需要继续增强；
- 视觉能力取决于底模是否为原生视觉模型；
- LINE 免费额度和 push/reply 规则受 LINE 官方限制；
- Cloudflare Tunnel 临时域名需要保持进程运行。

## 10. 成功指标

工程指标：

- 一键启动成功率；
- 模型切换后显存释放稳定性；
- LINE webhook 成功率；
- TTS 失败回退率；
- 会话恢复成功率；
- 长时间挂载稳定性。

角色指标：

- 是否保持身份；
- 是否保持语气；
- 是否保持边界；
- 是否能记住共同经历；
- 是否避免把用户偏好写成角色 canon；
- 是否在短回复/语音/图片下仍像同一个角色。

M5.2 已加入规则版 persona kernel 评分器，先把这些指标转成可自动报警的低成本检查。它不会取代人工判断，也不是论文级评测；它的产品价值是防止“突然变成通用助手”“用户一句话改写人格”“平台模式覆盖角色自主性”这类明显退化。

M4.6 已把记忆产品化为 Memory OS 层：短期原文、中期摘要、长期偏好/关系、图谱、矛盾链、反思笔记。用户未来看到的不再只是散乱 memory，而是一套可解释的记忆状态。

用户指标：

- 第一次启动用时；
- 用户需要手写代码的次数；
- 配置出错后的可理解程度；
- 训练数据准备成本；
- 接入 LINE 的步骤清晰度。

## 11. 推荐下一步

1. 将产品安装流程固化成“第一次启动向导”。
2. 把 `roleweaver.config.csv` 的字段解释做进 Web 设置面板。
3. 为 persona regression 增加第二模型 judge 和人工复核报告。
